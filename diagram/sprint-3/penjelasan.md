# Penjelasan Activity Diagram Sprint 3

## 1. Activity Diagram Ubah Profil (diagram_ubah_profile)

Gambar Activity Diagram Ubah Profil menunjukkan alur proses pengubahan data profil pengguna dengan cara admin membuka halaman Pengaturan Profil sehingga sistem memuat dan menampilkan data profil pengguna yang sedang aktif, meliputi nama, email, role, dan foto profil. Email dan role ditampilkan dalam kondisi nonaktif sehingga tidak dapat diubah. Admin kemudian mengubah data yang diinginkan pada form yang tersedia, yaitu nama, foto profil dalam format JPG atau PNG, password baru beserta konfirmasi password baru. Apabila admin ingin membatalkan perubahan yang belum disimpan, admin dapat menekan tombol Reset untuk mengembalikan seluruh nilai form ke kondisi semula. Setelah form diisi, admin menekan tombol Simpan untuk memicu sistem memvalidasi seluruh input. Sistem memeriksa bahwa nama tidak kosong, format password valid minimal delapan karakter tanpa spasi, serta password baru dan konfirmasi password harus cocok. Apabila terdapat kesalahan, sistem menampilkan pesan error pada field yang bersangkutan dan admin dapat memperbaiki isian. Apabila seluruh validasi berhasil, sistem menyimpan perubahan profil ke basis data dan menampilkan toast notifikasi sukses. Tombol Simpan hanya aktif apabila terdapat perubahan pada form (isDirty) sehingga mencegah pengiriman data yang tidak berubah.

## 2. Activity Diagram Manajemen Master Data Pembeli (diagram_manajemen_master_data_pembeli)

Gambar Activity Diagram Manajemen Master Data Pembeli menunjukkan alur proses menambah, mengubah, dan mengubah status data pembeli dengan cara admin membuka halaman Master Data Pembeli sehingga sistem memuat dan menampilkan daftar seluruh data pembeli yang tersedia. Admin kemudian memilih salah satu aksi yang tersedia yaitu tambah, ubah, atau ubah status. Ketika admin memilih aksi tambah, sistem menampilkan sheet form isian yang terdiri dari nama pembeli, jenis pembeli, nomor telepon yang bersifat opsional, email yang bersifat opsional, dan alamat. Setelah form diisi, admin menekan tombol Simpan untuk memicu sistem memvalidasi seluruh input. Apabila validasi gagal, sistem menampilkan pesan error pada field terkait dan admin dapat memperbaiki isian. Apabila validasi berhasil, sistem menyimpan data pembeli baru ke basis data, menampilkan toast notifikasi sukses, menutup sheet, dan memperbarui daftar pembeli. Ketika admin memilih aksi ubah, admin terlebih dahulu memilih data pembeli yang akan diedit sehingga sistem menampilkan sheet form dengan nilai yang sudah terisi sebelumnya, kemudian admin mengubah field yang diinginkan dan menekan tombol Simpan Perubahan. Sistem memvalidasi perubahan dengan alur yang sama seperti pada aksi tambah. Apabila valid, perubahan disimpan dan daftar diperbarui. Ketika admin memilih aksi ubah status, admin menekan tombol switch pada baris data pembeli yang dipilih sehingga sistem memperbarui field deletedAt pada basis data untuk mengaktifkan atau menonaktifkan pembeli tersebut secara soft delete, kemudian menampilkan toast notifikasi sukses dan memperbarui tampilan status pada tabel.

## 3. Activity Diagram Manajemen Inventaris (diagram_inventaris_crud)

Gambar Activity Diagram Manajemen Inventaris menunjukkan alur proses menambah, mengubah, mengubah status, dan mengelola stok data inventaris dengan cara admin membuka halaman Inventaris sehingga sistem memuat dan menampilkan daftar inventaris beserta empat kartu statistik yaitu total produk inventaris, jumlah produk di atas stok minimum, jumlah produk di bawah stok minimum, dan jumlah produk yang habis stoknya. Halaman ini juga menampilkan grafik persediaan stok dan grafik penggunaan produk. Admin kemudian memilih salah satu aksi yang tersedia yaitu tambah, ubah, ubah status, atau kelola stok. Ketika admin memilih aksi tambah, sistem menampilkan sheet form isian yang terdiri dari produk dengan tipe inventaris yang belum terdaftar dan stok minimum. Setelah form diisi, admin menekan tombol Simpan untuk memicu sistem memvalidasi seluruh input. Apabila validasi gagal, sistem menampilkan pesan error pada field terkait. Apabila validasi berhasil, sistem menyimpan data inventaris baru ke basis data dengan nilai totalQuantity awal nol, menampilkan toast notifikasi sukses, menutup sheet, dan memperbarui daftar inventaris. Ketika admin memilih aksi ubah, admin memilih data inventaris yang akan diedit sehingga sistem menampilkan sheet form dengan nilai yang sudah terisi. Field produk tidak dapat diubah saat pengeditan, sehingga hanya stok minimum yang dapat diperbarui. Sistem memvalidasi perubahan dan apabila valid akan menyimpan perubahan beserta menampilkan notifikasi sukses. Ketika admin memilih aksi ubah status, sistem memperbarui field deletedAt pada basis data untuk mengaktifkan atau menonaktifkan data inventaris tersebut, kemudian menampilkan notifikasi sukses. Ketika admin memilih aksi kelola stok, sistem menavigasi admin ke halaman Detail Inventaris yang memiliki fitur pengelolaan transaksi stok masuk dan keluar.

## 4. Activity Diagram Detail Inventaris dan Transaksi Stok (diagram_inventaris_stock_in_out)

Gambar Activity Diagram Detail Inventaris dan Transaksi Stok menunjukkan alur proses melihat riwayat stok dan mencatat transaksi stok masuk. Admin membuka halaman Detail Inventaris sehingga sistem memuat dan menggabungkan tiga sumber data yaitu catatan inventaris manual (notes), pengajuan inventaris yang telah disetujui (submission approved), dan catatan konsumsi inventaris (consumption). Sistem menampilkan empat kartu statistik yaitu total stok saat ini, total barang masuk, total barang keluar, dan total kejadian in/out. Admin dapat memilih aksi filter tanggal, pilih tab, lihat detail catatan, atau tambah stok. Ketika admin memfilter tanggal, sistem memperbarui tampilan berdasarkan rentang yang dipilih dan tombol reset tersedia untuk menghapus filter. Terdapat tiga tab yaitu Ringkasan dan Grafik untuk overview statistik, Data Tabel untuk riwayat transaksi beserta tombol tambah stok, dan Laporan untuk laporan tercetak. Ketika admin memilih tambah stok, sistem membuka sheet form berisi tipe transaksi (Grant atau Non-Grant), jumlah stok, catatan, foto bukti, serta data transaksi berupa tanggal, harga per item, catatan transaksi, dan foto bukti nota. Total harga dihitung otomatis dari harga per item dikali jumlah stok. Setelah admin menekan Simpan, sistem memvalidasi input. Apabila gagal, pesan error ditampilkan. Apabila berhasil, sistem menampilkan popup konfirmasi. Jika dikonfirmasi, transaksi disimpan, total stok diperbarui, dan toast sukses ditampilkan. Jika dibatalkan, toast pemberitahuan pembatalan ditampilkan.

## 5. Activity Diagram Pengajuan Inventaris (diagram_pengajuan_inventaris)

Gambar Activity Diagram Pengajuan Inventaris menunjukkan alur peninjauan dan pembaruan status pengajuan inventaris. Admin membuka halaman Pengajuan Inventaris sehingga sistem memuat daftar pengajuan beserta empat kartu statistik yaitu total pengajuan, pending, disetujui, dan ditolak. Admin dapat memilih aksi filter rentang tanggal, lihat detail, atau tinjau pengajuan. Filter rentang tanggal memperbarui daftar dan statistik berdasarkan tanggal pembuatan. Tombol detail menavigasi ke halaman detail pengajuan berisi informasi lengkap pengaju, produk, jumlah, catatan, status, riwayat tinjauan, dan data transaksi jika telah disetujui. Tombol edit pada pengajuan berstatus pending membuka sheet Edit Pengajuan dengan ringkasan barang dan pilihan status baru. Apabila status Ditolak dipilih, admin wajib mengisi alasan penolakan. Apabila status Disetujui dipilih, admin wajib mengisi data transaksi yaitu tipe (Grant/Non-Grant), tanggal, harga per item, catatan, dan foto bukti. Total harga dihitung otomatis dari harga per item dikali jumlah barang. Setelah Simpan ditekan, sistem memvalidasi input. Jika gagal, pesan error ditampilkan. Jika berhasil, popup konfirmasi muncul. Jika dikonfirmasi, perubahan disimpan dan data diperbarui. Jika dibatalkan, toast pemberitahuan ditampilkan. Pengajuan yang sudah disetujui atau ditolak tidak dapat diedit kembali.

## 6. Activity Diagram Laporan Sampling (diagram_menampilkan_laporan_sampling)

Gambar Activity Diagram Laporan Sampling menunjukkan alur melihat dan memfilter data laporan sampling ikan. Admin membuka halaman Laporan Sampling sehingga sistem memuat dan menampilkan seluruh data dari API. Admin dapat mengatur filter (rentang tanggal, kolam, siklus, dan petugas), mereset filter, melihat detail, atau mengganti tab. Filter siklus bergantung pada kolam yang dipilih terlebih dahulu. Sistem memproses filter secara langsung dan memperbarui tampilan. Tombol Reset Filter mengembalikan seluruh filter ke nilai awal. Tombol detail menampilkan sheet berisi foto bukti, jumlah sampling (ekor), berat rata-rata (gram), tanggal laporan, nama petugas, serta informasi kolam dan siklus terkait. Terdapat dua tab yaitu Ringkasan dan Grafik untuk overview statistik dan tren, serta Data Tabel untuk tabel data yang dapat difilter.
